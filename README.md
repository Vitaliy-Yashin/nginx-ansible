# 🌐 Nginx: Централизованное управление конфигурацией через IaC

## 📝 Введение

Протокол HTTP является основой для разработки сетевых приложений — будь то фронтенд или бэкенд. Дальнейшей обработкой запросов занимается веб-сервер или обратный прокси в зависимости от цели: отдать статику или перенаправить запрос бэкенду.

С этой задачей отлично справляется всеми известный Nginx.

## ❌ Проблема

Доменное имя может иметь несколько A-записей, соответственно, несколько серверов могут обслуживать один домен. Это значит, что конфигурация Nginx может потребоваться на множестве машин. Если настраивать каждый сервер вручную, возникает риск ошибок, теряется время и сложно поддерживать единообразие.

## ✅ Решение

Чтобы избежать этих проблем, я организовал централизованное управление конфигурацией Nginx с использованием подхода Infrastructure as Code (IaC). В качестве инструмента выбран Ansible.

Этот проект позволяет быстро развернуть и настроить Nginx на нескольких серверах с единым подходом.

## ✨ Что умеет этот проект

- 🚀 Разворачивает `nginx`
- 📝 Перезаписывает дефолтный конфиг
- ⚙️ Настраивает параметры для `nginx.conf`
- 🔐 Добавляет аутентификацию через `basic_auth`
- 🔐 Копирует SSL-сертификаты и приватные ключи на сервер (при наличии)
- 📂 Копирует из репозитория конфигурационные доменные блоки на конечные сервера
- 🐳 Устанавливает `docker` через роль и разворачивает `nginx-prometheus-exporter`

## ⚙️ Требования к окружению
Проект протестирован и гарантированно работает в следующей конфигурации:

### 💻 На управляющем узле -Control Node (Место, откуда вы запускаете плейбук )
* **Ansible:** `2.16.3` (на этой версии велась разработка. Проверить свою версию: `ansible --version`).
* **Python:** `3.12.3`

### 🖥️ На целевых серверах (из hosts.ini)
* **ОС:** Ubuntu / Debian (плейбук настраивает конфигурацию для Linux систем).
* **Служба SSH:** На каждом сервере должен быть установлен и запущен `ssh-server`.
* **Доступ по ключу:** Управляющий узел должен подключаться к удаленным серверам по SSH-ключу без ввода пароля.
* **Права Ansible-пользователя:** Пользователь, под которым Ansible подключается к серверам (например, пользователь с правами sudo), должен иметь возможность выполнять команды с повышением привилегий (`become: true`) **без запроса пароля** (настройка `NOPASSWD` в sudoers на целевой машине). Это необходимо, так как проект управляет

## 📂 Структура проекта
```text
.
├── files/                        # Системные конфигурационные файлы
│   ├── sites-available           # Директория с доменными конфигурационными файлами
│   ├── certs                     # Директория с SSL-сертификатами
│   ├── basic_auth                # Директория с httpasswd для каждого доменного имени (файл для аутентификации)
│   └── nginx.conf                # Главный конфигурационный файл службы nginx
├── roles/                        # Директория с логикой автоматизации (роли)
│   ├── nginx_install_packages    # Роль для установки nginx через apt
│   ├── default_site              # Роль для копирования дефолтного сайта из files на конечные узлы
|   ├── nginx_conf                # Роль для копирования nginx.conf из files на конечные узлы
│   ├── basic_auth                # Роль для копирования httpasswd из files на конечные узлы
│   ├── sites-available           # Роль для копирования доменных конфигурационных файлов
│   ├── geerlingguy.docker        # Роль для устновки docker
│   └── nginx-prometheus-exporter # Роль для развертывания exporter 
├── hosts.ini                     # Настройки подключения к вашим серверам
├── playbook.yml                  # Главный файл для запуска всех ролей
└── requirements.yml              # Внешние роли и коллекции Ansible
```

## 🚀 Как запустить

1. **Клонировать репозиторий:**
```bash
git clone https://github.com/Vitaliy-Yashin/nginx-ansible.git && cd nginx-ansible
```
2. **Настроить инвентарь в hosts.ini:**
```ini
[locals]
192.168.92.145 ansible_port=22 ansible_user=vitaliy
192.168.92.138 ansible_port=22 ansible_user=vitaliy
```

```markdown
> Важно: Для корректной работы SSL-сертификатов на сервере должны присутствовать приватные ключи. Они не хранятся в репозитории — их нужно сгенерировать заранее или скопировать вручную. Рекомендуется разместить их в защищённом месте (например, в зашифрованном хранилище) и передавать через Gitlab переменные или отдельный механизм.
```
Поэтому для каждого доменного имени, для которых есть ssl сертификат в `files/certs` должна быть такая структура.
```text
.
├── files/
│   └── certs
│       └── example.com
│           ├── example.com.crt #Сертификат
│           └── example.com.key #Приватный ключ к сертификату
```

3. **Установить зависимости**
```bash
ansible-galaxy install -r requirements.yml --force
```

4. **Запуск плейбука:**
```bash
ansible-playbook -i hosts.ini playbook.yml
```
